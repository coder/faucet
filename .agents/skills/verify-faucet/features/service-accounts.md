# Service accounts

A service agent, such as one that analyzes GitHub events, logs in to faucet with a client ID and secret that an operator made ahead of time, with preset grants and no GitHub token. Every MCP client that connects without a token finds faucet's login server by standard discovery, at `FAUCET_PUBLIC_URL`, which faucet needs to start.

## Sub-features

- `faucet clients create [-resource <url>] [-scope <scopes>] -grant repo:<owner>/<name>|org:<login>|all <client-id>` prints the client ID and a `fcs_` secret once; `-resource` defaults to `$FAUCET_PUBLIC_URL/github/mcp` and must be that when the variable is set, and `/mcp` takes no new client. `faucet clients list` shows every client without a secret. `faucet clients disable <client-id>` ends one and deletes its subscriptions. It leaves the poll leases of [raw events](raw-events.md) that the service holds, which end 60 minutes after their last poll. The commands read `DATABASE_URL`. An ID is never given to a second client.
- Every 401 from `/github/mcp` and `/mcp` carries `WWW-Authenticate: Bearer resource_metadata="<origin>/.well-known/oauth-protected-resource<path>", scope="events:read events:subscribe"`, and each path serves its own metadata document, whose `resource` is the path's URL.
- `/.well-known/oauth-authorization-server` names `/oauth/authorize`, which answers 400 `unsupported_response_type` until a grant uses it (the TypeScript MCP SDK needs the field), and `POST /oauth/token`, which takes `client_credentials` with HTTP Basic client authentication. A token request without `resource` gets the client's endpoint, and the token holds the scopes asked for that the client holds. The token lasts 15 minutes and works only on the client's endpoint. A client for another server's endpoint gets `invalid_client`.
- A service may wait on a repository that a `repo:` grant names, matched by name, or that an `org:` grant covers by its owner's ID, or any with `all`, once a signed delivery named it: every signed delivery records the repository it names, stored or ignored, under the name it was first seen with until a `repository` renamed or transferred delivery changes it. Faucet takes each such body once, so the same body under another delivery GUID changes nothing; one from a name that faucet does not hold logs `a rename or transfer of the repository never reached faucet` and quarantines the repository, which then answers to no name until a fresh rename from the name faucet holds, unless redelivery asked for it, which changes nothing; and one whose write fails is answered 500. Before that the wait tool says faucet has received no delivery from it yet. A repository no grant covers is refused with that reason. The `owner` and `all` targets of `org:` and `all` grants are in [Owner targets](owner-targets.md).
- A service polls and subscribes to the [raw events](raw-events.md) of a granted repository as it does to the typed ones. A raw delivery that nobody wants is 202 `ignored` with no row in `faucet_raw_events`, and it still records the repository. So the first `events/poll` of a raw name after that delivery opens the lease, and the next delivery is stored for it.
- A disabled client gets no new token, and its token fails on its next request.
- `faucet clients update <client-id> [-scope <scopes>] [-grant <grant> ...]` replaces the scopes, the grants or both of a live client and keeps its ID, secret and trust rules. A token of the client takes the new grants on its next request and holds only the scopes that it was issued with and the client holds, so a new scope needs a new token. Leaving out `events:subscribe` deletes the client's subscriptions, and an `org:` grant that the client holds stays bound to its account.
- A workload logs in with its platform's OIDC token instead of a secret: `faucet clients create -no-secret` makes a client with no secret, and `faucet clients trust <client-id> -issuer <url> -claim <name>=<value> [-jwks-file <path>]` adds a trust rule (`trusts` lists them, `untrust` removes one). `POST /oauth/token` takes `grant_type=urn:ietf:params:oauth:grant-type:token-exchange` with `client_id` in the form and the workload's JWT as `subject_token`, and answers the client's token with `issued_token_type`. Before the subject token's signature verifies under a rule of the client, every refusal (an unknown or disabled client, one with no trust rule, a token that no rule verifies) gets one 400 `invalid_client` with the same description, and the log says why. After it verifies, a refused token gets `invalid_request` with the reason, and a failed fetch of the issuer's keys, when faucet holds no key of the token's `kid`, 503 `temporarily_unavailable` with `Retry-After` set to the seconds until the next fetch. A `kid` that keys fetched less than a minute ago lack gets the 400 `invalid_client`.
- `/cron/purge` deletes expired access tokens and counts them in `expired_access_tokens`.
- Without `FAUCET_PUBLIC_URL` (or, on Vercel production, `VERCEL_PROJECT_PRODUCTION_URL`), faucet exits 1 at startup and names the variable (`tests/startup.e2e.ts`).

## How to get to it (user POV)

An operator runs `faucet clients create` against the production database and gives the service the endpoint URL, the client ID and the secret. The service's MCP client (here go-sdk's `extauth.ClientCredentialsHandler`) needs nothing else: it reads the 401, the metadata and the token endpoint on its own.

## Driving it with e2e

`tests/service-accounts.e2e.ts` starts a faucet with `withFaucet`, which sets `FAUCET_PUBLIC_URL` to its own URL, makes clients with the real `faucet clients` command (`Faucet.clients`, through `createClient` of `tests/services.ts`), delivers a workflow_run whose payload names the repository in full, and runs `cmd/faucet/internal/serviceagent`, a go-sdk client built by `app.mjs`, with the URL, the client ID and the secret (`Faucet.serviceAgent`). A second test logs in with the TypeScript MCP SDK's `ClientCredentialsProvider` (`@modelcontextprotocol/sdk`, pinned in `package.json`). Another logs a workload in through the same SDK with a token exchange provider (the SDK's `StaticPrivateKeyJwtProvider` with `prepareTokenRequest` and `addClientAuthentication` swapped), against the `issuer` fixture of `tests/support.ts`: an OpenID issuer on `https://127.0.0.1:<port>` that serves its discovery document and key set with the certificate that `app.mjs` wrote, and signs tokens in Node. That faucet runs the e2e build (`{ e2eBuild: true }`), whose key client reaches loopback, and `SSL_CERT_FILE` makes it trust that certificate. A third test gets a token from `POST /oauth/token` with HTTP Basic (`accessToken`) and polls `github.push` with it (`Faucet.mcp` with `token`): denied before any delivery, a lease after an ignored push, then the next push. The last test disables a client: it logs in no more, and `faucet clients list` says when it was disabled. The Go test `TestTheMCPAliasHasItsOwnDiscovery` logs a client of `/mcp` in, since the command makes none. Live: not reachable from a browser, use `run_tests {files: ["tests/service-accounts.e2e.ts"]}`.

## Proof

The agent exits 0 with a wait result that holds the delivered `ci.run_completed` event, and exits 1 once the client is disabled. The raw poll returns the push that arrived after the lease, with the payload as `data`, and `faucet_repos` holds the row that the ignored push wrote. The 401 header and the metadata documents match byte for byte. The Go tests in `cmd/faucet/login_internal_test.go` run the same client against the router as `run()` builds it; `faucet/oauth/server_test.go` pins the token endpoint's answers.

## Charters

```
service-token-endpoint|http|skeptic|Send POST /oauth/token with every mix of Basic and form credentials, URL-encoded and not, wrong secrets, disabled clients, scopes and resource values, and report any answer that differs from RFC 6749 section 5 or issues a token it should not
service-discovery|http|skeptic|Fetch every 401 and metadata document on /github/mcp and /mcp, with no token, a GitHub token and tokens that faucet did not mint, and report any resource, issuer or URL that a client could not match byte for byte
```

## Gotchas

- `FAUCET_PUBLIC_URL` must be the URL that clients call, in the form they compute: no trailing slash, no default port, a lower-case host. faucet refuses to start otherwise.
- A `repo:` grant matches a repository by name. After a rename, the grant must name the new name, and faucet learns the rename only from a `repository` delivery. An `org:` grant matches by the owner's ID, which `faucet clients create` takes from faucet's owners when it makes the client, so a delivery of the owner or any repository of it must come first.
- `-grant` takes one grant; repeat it for more. `createClient` of `tests/services.ts` passes `-scope events:read` unless told otherwise, so a test that subscribes passes `events:read,events:subscribe`, comma separated.
